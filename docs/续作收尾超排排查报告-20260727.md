## 二、根因定位（真实链路）

### 2.1 收尾目标量正确（非根因）

`DefaultEndingJudgmentStrategy.resolveTailTargetQty` + `TargetScheduleQtyResolver.upsizeEndingTargetQty`：
- 共用胎胚 → baseTargetQty = surplusQty = 42
- roundUp(42, mouldQty=2) = 42
- **targetScheduleQty = 42（正确，无放大）**

日志佐证：`S4.4续作目标量决策, adoptedTargetQty: 42, rule: 单机台收尾共用胎胚仅按余量`

### 2.2 班次1-3分配正确（非根因）

`distributeToShifts` 按目标量42分配：
- 班次1: 16, remaining=26
- 班次2: 16, remaining=10
- 班次3: 10（尾班）, remaining=0
- 合计42，符合目标量

### 2.3 共用胎胚收尾错峰后延（★真正根因★）

**文件**：`ContinuousProductionStrategy.java`
**方法**：`applySharedEmbryoEndingStaggerPostpone`（第5416行）

**触发条件**：
1. `isEndingAutoFillEnabled(context)` = true（收尾自动补量开关开启）
2. SKU 为共用胎胚收尾（sharedEmbryo=true，2个SKU共用胎胚215102417）
3. 存在可后延的下一班次

**执行逻辑**（`applySharedEmbryoEndingStaggerPostponeResult` 第5897-5929行）：

```java
// 第5899行：计算班次4可用产能
int nextShiftCapacity = calculateResultShiftCapacity(context, result, nextShift);  // =16
// 第5909行：换胶囊后实际可排量
int actualNextShiftQty = capsuleReplacementRuleService.resolveActualPlanQty(
        context, result, nextShift, nextShiftCapacity, "共用胎胚收尾错峰后延");  // =16
// 第5920行：★直接在班次4追加排产16★
setShiftPlanQty(result, nextShift.getShiftIndex(), actualNextShiftQty, ...);
// 第5926行：计算允许超量并登记
int afterQty = ShiftFieldUtil.resolveScheduledQty(result);   // 58
int allowedOverQty = Math.max(0, afterQty - beforeQty);      // 58-42=16
context.getSharedEmbryoEndingStaggerAllowedOverQtyMap().merge(result, allowedOverQty, Integer::sum);
```

### 2.4 账本不裁剪（超排保留）

`TargetScheduleQtyResolver.capResultByProductionRemainingQty`（第855-873行）：

```java
int remainingQty = resolveEffectiveProductionRemainingQty(context, sku);  // 42
int allowedOverQty = resolveEndingAllowedOverQty(context, result);        // 16（错峰后延登记）
int retainedLimitQty = remainingQty + allowedOverQty;                     // 42+16=58
if (resultQty <= retainedLimitQty) { return resultQty; }                  // 58<=58，不裁剪
```

### 2.5 业务意图

"共用胎胚收尾错峰后延"设计目的：多个SKU共用同一胎胚时，为避免在同班次集中收尾导致胎胚库存分配冲突/换模拥挤，将本SKU收尾班次从3后延到4，并在班次4追加一个满班（16）作为缓冲。后延的16记为"允许超量"，不触发严格收口。

| 项目 | 说明 |

| 模台数 | **2** |
| 班次4排量 | **16**（班次4可用产能=单模班产16） |
| 超排量 | **16** |
| 根因 | 共用胎胚收尾错峰后延（applySharedEmbryoEndingStaggerPostpone）在班次4主动追加16 |
| 触发条件 | 共用胎胚(sharedEmbryo=true) + 收尾(isEnding) + isEndingAutoFillEnabled开关开启 |
| 未拦截原因 | 后延补量登记为"允许超量"，capResultByProductionRemainingQty 按 余量+允许超量 不裁剪 |

## 四、解决方案

### 方案一：关闭收尾自动补量开关（最小改动 · 推荐）

**改动点**：参数 `ENDING_AUTO_FILL_ENABLED` 置 0（或 config.isEndingAutoFillEnabled()=false）

**位置**：
- `LhScheduleConstant.ENDING_AUTO_FILL_ENABLED`
- `LhScheduleParamConstant.ENDING_AUTO_FILL_ENABLED`
- `LhScheduleConfig.isEndingAutoFillEnabled()`

**效果**：`applySharedEmbryoEndingStaggerPostpone` 第5422行直接 return，不再触发错峰后延，收尾严格按目标量42，班次4不排。

**影响范围**：所有共用胎胚收尾SKU不再错峰后延。

**风险**：共用胎胚的多个SKU可能在同一班次收尾，需确认胎胚库存分配是否冲突。若业务上不需要错峰，此方案最稳妥。

### 方案二：错峰后延只移动收尾时间，不追加产量

**改动点**：`applySharedEmbryoEndingStaggerPostponeResult`（第5920行）

**改动**：移除 `setShiftPlanQty(result, nextShift.getShiftIndex(), actualNextShiftQty, ...)`，只更新收尾时间 `result.setIsEnd("1")` + `syncMachineEstimatedEndTime`，不在班次4追加产量。

**效果**：保留错峰后延的收尾时间移动效果，但班次4不排产，不超排。

**风险**：后延后班次4无产量，收尾时间可能与实际生产不符；机台释放时间提前，需确认不影响后续换模/新增排产。

### 方案三：错峰后延补量从下一共用SKU借用

**改动点**：`applySharedEmbryoEndingStaggerPostponeResult` + 账本逻辑

**改动**：后延新增的16不从当前SKU超排，而是预占另一共用SKU的额度，当前SKU仍按余量42收尾。

**效果**：错峰且不超排，胎胚库存分摊更均衡。

**风险**：实现复杂，需调整 sharedEmbryoEndingStaggerAllowedOverQtyMap 和生产消费账本，改动量大。

## 五、推荐方案

**推荐方案一（关闭开关）**，理由：
1. 改动最小（仅参数/配置），不动代码逻辑
2. 从源头关闭错峰后延，班次4不再追加
3. 可通过参数动态调整，便于验证和回退
