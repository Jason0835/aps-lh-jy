# 硫化机精度计划排程规则

**状态：已实现** | **最近修订：2026-07-26** | **适用链路：基础数据、续作、换活字块、新增排产、机台时间轴、结果校验、完成事件回填**

## Purpose

统一硫化机年度精度计划的加载、优先级、执行日期、执行日前06:00生产截止、前置小余量插排、
3天内强制下机、胶囊预热、班次原因及安排日期回填口径。在不突破每日台数、周日、节假日、
盘点日、设备停机、清洗和维修约束的前提下，允许利用精度前空闲时间，但任何生产或准备任务
均不得影响精度按期执行。

精度默认在最终执行日08:00开始、持续7小时，结束后预留2.5小时胶囊预热，默认最早17:30恢复生产。
生产、换模、换活字块和首检必须在执行日06:00前完整完成，或从胶囊预热结束后开始。

## 数据加载与优先级

### Requirement: 运行态计划必须同时满足计划日期和 daysToDue

运行态查询 MUST 加载工厂和年度匹配、未删除、`completionStatus=0`、`actualDate IS NULL`、
`planDate IS NOT NULL`、`planDate >= T`、`daysToDue IS NOT NULL` 且
`daysToDue <= SYS0307003` 的精准计划。`planDate >= T` 是运行态触发的首要日期前提：
精度允许从T日起在计划日前提前执行，但计划日期早于T日的历史计划不得延后到本轮执行。
查询 MUST NOT 使用 `scheduleDate IS NULL` 过滤，已安排但尚未实际执行的合格计划仍可重新决策。

满足 `planDate >= T` 后，`daysToDue` 是30天预警和3天强制分级的唯一口径，系统 MUST NOT 使用
`dueDate`、`planDate` 与排程日重新计算 `daysToDue`。`planDate` 同时作为最终允许执行日期；
最终执行日不得晚于 `planDate`。`planDate` 或 `daysToDue` 为空时均不进入调度，并记录缺少触发依据。

系统 SHALL 同时保留完整有序计划列表和按机台查询的兼容 Map。有序列表必须按以下顺序稳定排序：

1. `daysToDue` 升序；
2. `planDate` 升序，空值排在最后；
3. L/R 合并后的物理机台编码升序。

同一物理机台在本批只处理最高优先级计划；L/R 两侧分别保留各自计划主键。

#### Scenario: 计划日期早于T日

- **Given** 精度计划未完成且实际执行日期为空，但 `planDate < T`
- **When** APS 加载运行态计划
- **Then** 该计划 MUST NOT 进入本轮精度调度
- **And** 系统不得把该计划延后到T日或T日之后执行

#### Scenario: 3天计划优先

- **Given** 同时存在 `daysToDue=2` 和 `daysToDue=10` 的计划
- **When** 系统分配每日精度额度
- **Then** `daysToDue=2` 的计划 MUST 先处理

#### Scenario: 同级按机台编码排序

- **Given** 两条计划的 `daysToDue` 和 `planDate` 相同
- **When** 系统排序
- **Then** 物理机台编码较小的计划 MUST 先处理

### Requirement: 年度计划完整性仅告警

每台启用硫化机每个自然年度应有一条精准计划。计划缺失或重复时，系统 MUST 同时写应用日志和
排程过程日志，但 MUST NOT 自动生成、删除或修改计划，也 MUST NOT 阻断其他机台排程。

## 参数

### Requirement: 精度参数必须兼容非法历史值

| 参数编码 | 业务含义 | 默认值 | 规则 |
| --- | --- | --- | --- |
| `SYS0307001` | 精度执行时长 | 7小时 | 精度结束 = 开始 + 时长 |
| `SYS0307002` | 精度固定开始小时 | 8 | 最终执行日08:00开始 |
| `SYS0307003` | 精度预警天数 | 30天 | `daysToDue <= 30` 进入调度 |
| `SYS0307005` | 是否允许周日精度 | 现有默认值 | `0`顺延，`1`允许 |
| `SYS0307006` | 节假日前禁排天数 | 2天 | 节假日及此前N天禁排 |
| `SYS0307007` | 强制精度天数 | 3天 | `daysToDue <= 3` 执行强制规则 |
| `SYS0307009` | 胶囊预热时长 | 2.5小时 | 精度结束后继续占用机台 |
| `SYS0307011` | 精度前插排最大计划量 | 50条 | 只接受完整真实待排量不超过该值的SKU |

`SYS0307011` 缺失、非数字或小于等于零时 MUST 使用50并输出参数告警。其他时长参数为空、
格式非法或为负数时使用现有业务默认值。每日精度数量继续执行现有一台物理机上限。

## 执行日期与06:00截止

### Requirement: 前SKU必须在执行日06:00前收尾

系统 MUST 使用完整班次产能、停机、清洗、维修、精度窗口和实际硫化节拍预测物理机台最晚收尾时间。
L/R 单控机台取两侧最晚收尾时间。判断边界固定为：

```text
预计收尾时间 <= 精度执行日06:00：满足
预计收尾时间 > 精度执行日06:00：不满足
```

满足时，前SKU正常生产至收尾，机台随后空等至08:00精度开始；等于06:00视为满足。

每个候选执行日 MUST 继续校验每日一台物理机、月末盘点日、周日参数、节假日及节假日前禁排、
设备停机、维修和清洗固定窗口。任一约束命中时可向后顺延并重新校验，但最终执行日不得晚于
`planDate`；计划日前没有合规日期时取消本轮安排。日期运算必须支持跨月和跨年。

#### Scenario: 06:00前自然收尾

- **Given** 前SKU预计在执行日05:59收尾
- **When** 系统安排精度
- **Then** 前SKU MUST 正常收尾
- **And** 机台 MUST 空等至08:00

#### Scenario: 恰好06:00收尾

- **Given** 前SKU预计恰好在执行日06:00收尾
- **When** 系统校验截止
- **Then** 该结果 MUST 视为满足

## 4至30天普通精准计划

### Requirement: 普通计划不得强制截断当前在机SKU

当 `4 <= daysToDue <= 30` 且最早合规执行日无法在06:00前自然收尾时，系统 MUST NOT 强制截断
MES在机SKU；应在计划日前继续寻找首个满足“自然收尾不晚于当天06:00”的合规执行日。

只有因前SKU晚于原候选日06:00而顺延、且最终仍不晚于计划日期的窗口才允许前置插排。
计划日前不存在自然收尾窗口时，本轮取消安排并记录原因，不得新增延后日期、兜底日期或强制分支。

中心预决策阶段若普通计划的在机SKU收尾时间仍未知，系统 MUST NOT 将未知误判为可在06:00前收尾。
该物理机台应记录为“待真实收尾补决策”；续作主链形成首个真实收尾时间后，必须按相同日期硬约束
补做一次执行日决策。若真实收尾晚于当日06:00并使精度顺延到后续合规日，则开放真实收尾至执行日
06:00之间的小余量插排窗口；补决策成功后必须清除暂缓标记，避免重复挂窗。

### Requirement: 前置插排必须完整排完小余量SKU

候选 SKU MUST 保持现有 SKU 排序和选机优先级，系统只增加以下过滤条件：

1. 真实生产余量和日计划待排量均大于零；
2. 完整真实待排量不超过 `SYS0307011`；
3. 本次结果总量等于完整待排量，禁止从大余量SKU截取50条；
4. 模具、规格、胎胚、胶囊、单控、最早可排日和提前生产规则全部满足；
5. 换模、换活字块、首检、晚班限制和换模次数上限全部满足；
6. 设备停机、维修、清洗及各班次实际产能测算后，最后一个正量班次完成时间不晚于06:00；
7. 准备任务及生产均不与精度和胶囊预热区间重叠；
8. 模数取整、收尾补满等逻辑不得造成超排。

候选首次失败时 MUST 使用现有局部资源回滚并继续原顺序中的下一候选。全部失败时不得安排新SKU，
机台保持空等。候选正式提交后必须记录对象身份，保存前再次核对最终班次时间；若最终时间超过06:00，
必须只撤销该插排结果，恢复生产余量和dayN账本，生成可对账未排记录并回退为空等，不在最终阶段
重新搜索候选。

新增排产按最早收尾班次筛选机台前，MUST 使用精度及胶囊预热时间轴修正候选机台的有效参考时间。
仍开放且尚未使用前置插排机会的机台继续使用原收尾时间，以便进入06:00前完整测算；不允许插排或
插排机会已经使用的机台，必须使用胶囊预热完成后的真实就绪时间参与候选分层。系统 MUST NOT 允许
原始收尾时间较早、但实际已被精度占用的机台成为最早候选基准并过滤其他真实可排机台。

#### Scenario: 精度不可排机台不得阻塞后续候选层

- **Given** 机台A原始收尾时间最早，但精度及胶囊预热使其真实就绪时间落到排程末段
- **And** 机台A完成换模后将超过排程窗口
- **And** 原排序中的机台B可在更早班次正常完成换模并生产
- **When** 系统构建最早收尾班次候选
- **Then** 机台A MUST 按精度调整后的真实就绪时间参与分层
- **And** 机台B MUST 保留在当前候选层并继续走现有排序和完整排产主链

#### Scenario: 小余量候选成功插排

- **Given** 顺延后的精度前存在空档，候选完整待排量为50条
- **And** 换型、首检及生产均可在06:00前完成
- **When** 候选走完现有排产主链
- **Then** 系统 MAY 插排完整50条

#### Scenario: 准备时间导致超时

- **Given** 候选待排量少于50条
- **And** 加入换模或首检后预计06:01完成
- **When** 系统校验完整时间轴
- **Then** 候选 MUST 被排除并记录具体原因

#### Scenario: 保持现有排序

- **Given** 多个候选均能在06:00前完整完成
- **When** 系统选择插排SKU
- **Then** MUST 选择现有SKU排序中最靠前的候选
- **And** MUST NOT 按完成时间重新排序

#### Scenario: 禁止超排和截断

- **Given** 候选完整待排量为80条，或计划结果只覆盖50条待排量中的40条
- **When** 系统判断插排
- **Then** 候选 MUST 被排除

#### Scenario: 最终时间变化触发撤销

- **Given** 插排候选初次测算在06:00前完成
- **And** 保存前最终班次时间变为06:01
- **When** 系统执行最终时间轴复核
- **Then** 插排结果 MUST 被撤销
- **And** 生产余量和dayN账本 MUST 恢复
- **And** 机台 MUST 空等至精度开始

## 3天内强制精度

### Requirement: 3天计划必须优先并执行真实强制下机

当 `daysToDue <= SYS0307007` 时，系统 MUST 占用排序后最早合规执行日，不再尝试插排。物理机台任一侧
无法在执行日06:00前收尾时，必须以06:00为实际强制下机截止点。

系统只保留06:00前可完成的班次量；跨越截止点的班次使用现有停机、清洗和真实节拍计算可保留量，
06:00后的数量全部截断。截断量 MUST 同步恢复：

1. SKU生产余量；
2. dayN日计划 `scheduledQty`、`remainingQty` 和 `actualQty`；
3. 机台班次剩余产能；
4. 未排结果，原因固定为“精度计划到期强制下机”。

零量结果不得落库；剩余有效结果必须重算班次量、结束时间和收尾标记。强制规则不再以连续在机超过30天
作为前置条件。

如果计划日前日期全部被每日台数、周日、节假日、盘点日或固定停机任务占用，系统 MUST 取消本轮安排，
不得突破硬约束，也不得顺延到 `planDate` 之后；同时必须输出 WARN 应用日志和排程过程日志说明
“计划日前无合规执行日，禁止延后执行”。

#### Scenario: 3天内触发强制下机

- **Given** `daysToDue=2` 且预计收尾晚于执行日06:00
- **When** 系统生成续作结果
- **Then** 06:00后的数量 MUST 被截断
- **And** 截断量、账本恢复量和未排量 MUST 相等
- **And** 未排原因 MUST 为“精度计划到期强制下机”

#### Scenario: 空闲机台不误判强制

- **Given** 机台当前没有在机SKU且预计收尾时间为空
- **When** 3天计划进行预决策
- **Then** 机台 MUST 视为排程日开始时已经就绪
- **And** MUST NOT 标记强制下机

## 单控物理机台与统一时间轴

### Requirement: L/R两侧必须作为同一物理机处理

L/R 两侧必须共享执行日期、06:00截止、强制标志和每日额度。任一侧未收尾时按两侧最晚完成时间判断；
任一侧触发强制时两侧均不得跨越截止。两侧窗口分别保留计划主键，完成事件按主键分别回填
`SCHEDULE_DATE`。

### Requirement: 精度与所有任务禁止重叠

精度不可生产区间为：

```text
精度开始 = 最终执行日08:00
精度结束 = 精度开始 + SYS0307001
最早开产 = 精度结束 + SYS0307009
```

生产、换模、换活字块、首检、清洗、维修和盘点任务不得与精度及胶囊预热占用区间重叠。
旧有“正规换模与精度并行”“维保重叠专用换型时长”和“试制换模清除精度窗口”语义废止。
冲突任务只能在06:00前完整完成，或整体顺延到预热结束后开始。计划性维修自身既有规则保持不变。

未来精度窗口超出当前固定班次范围时不得提前锁死当前机台；只有任务可能跨越06:00或精度占用区间时
才施加约束。设备停机、清洗、维修与精度日期冲突时，执行日期选择阶段可在计划日前顺延；
无法在计划日前解决冲突时必须排除该次精度安排。

## 日志、结果原因与回填

### Requirement: 日志必须完整还原决策

应用日志和排程过程日志 MUST 覆盖：

- 机台、计划日期、`daysToDue`、是否命中30天及3天强制；
- 全局排序结果；
- 前SKU及预计收尾、是否满足06:00；
- 原顺序候选列表及每个候选的待排量、准备时间、开产时间、完成时间；
- 候选接受或排除的具体原因；
- 强制下机截止、截断量、账本恢复量和固定未排原因；
- 无候选或最终撤销后的空等结论；
- 计划日期准入、计划日前无合规日期及禁止延后执行原因；
- 最终精度开始、结束和最早开产时间。

日志不得在容量循环中重复刷屏，也不得为记录日志重建另一套候选排序或过滤逻辑。

### Requirement: 精度所在班次原因固定为精度计划

精度结束时间进入本批固定班次范围时，系统 MUST 在对应班次原因分析中写入固定文本：

```text
精度计划
```

由于新规则禁止精度与换模并行，系统 MUST NOT 再生成“换模+精度计划”。读取历史重叠结果时也统一
输出“精度计划”，其他清洗和维修原因按现有规则保留。未来精度尚未进入当前班次范围时，不得污染
当前结果班次原因。

### Requirement: 完成事件按计划主键回填安排日期

排程结果成功保存后，完成事件监听器 MUST 遍历实际挂载窗口，按 `precisionPlanId` 去重并使用独立事务
回填 `SCHEDULE_DATE=beginOfDay(maintenanceStartTime)`。回填失败必须记录批次、工厂和计划主键，
但不得回滚已经成功保存的排程结果。不得新增数据库表、字段、Mapper 或 XML。
